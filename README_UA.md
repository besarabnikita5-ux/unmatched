# Unmatched — веб-версія

Веб-сайт повторює застосунок: персонажі й поля з коробками та іконками, звичайна гра (2–4 гравці, команди, відхилення, таймер), турнірний режим, акаунти, статистика, історія, теми (14 + власна), українська й англійська мови, резервні копії (**той самий формат, що в Android**), офіційний каталог — і **приєднання до кімнат, створених в Android-застосунку**.

## 1. Як це працює 

Android-застосунок передає гру по звичайному TCP (порт 45678) і шукає ігри через mDNS. **Браузер так не вміє** — це обмеження всіх браузерів, не сайту. Тому поруч із сайтом є крихітна програма-**міст** (`bridge/`, Node.js): вона приймає WebSocket від сайту й пересилає рядки в TCP кімнати Android-хоста, а також шукає ігри в мережі.

```
  Браузер (сайт)  ──WebSocket──▶  Міст на комп'ютері  ──TCP──▶  Телефон-хост (Android-застосунок)
```

- Усе, крім мережевих ігор (звичайна гра, турнір, статистика, теми…), **працює без мосту**.
- Міст запускається на комп'ютері, що в **одній Wi-Fi мережі** з телефоном-хостом.
- **Сайт вміє лише приєднуватись** до кімнат. Створювати кімнату (бути хостом) може тільки Android-застосунок: браузер не може приймати вхідні з'єднання.

## 2. Структура файлів

```
UnmatchedWeb/                      ← корінь сайту (саме цей вміст завантажується на GitHub)
├── index.html                     ← сторінка
├── manifest.webmanifest           ← «Встановити як застосунок» (PWA)
├── sw.js                          ← кеш для роботи без інтернету
├── .nojekyll                      ← щоб GitHub Pages віддавав файли «як є»
├── css/
│   └── style.css                  ← стилі (адаптивні: телефон, планшет, ПК)
├── js/                            ← підключаються саме в такому порядку (див. index.html)
│   ├── data.js                    ← каталог коробок, 14 тем, переклад EN (згенеровано з вашого Kotlin-коду)
│   ├── util.js                    ← допоміжні функції, SHA-256/HMAC/PBKDF2
│   ├── i18n.js                    ← мови
│   ├── store.js                   ← сховище: акаунти, статистика, історія, резервні копії
│   ├── net.js                     ← мережевий клієнт кімнати (протокол Android-застосунку)
│   ├── ui.js                      ← діалоги, іконки, анімація
│   ├── dialogs1.js                ← статистика, акаунт, теми, мова, резервна копія, каталог
│   ├── dialogs2.js                ← турнір, приєднання до гри, кімната
│   └── app.js                     ← головний екран, звичайна гра, запуск
├── icons/                         ← іконки застосунку (icon.svg, icon-192.png, icon-512.png)
├── assets/
│   └── catalog/
│       ├── characters/            ← сюди іконки персонажів (<id>.png) — див. п. 3
│       └── maps/                  ← сюди зображення полів (<id>.png)
└── bridge/                        ← міст; на комп'ютері, НЕ потрібен для хостингу
    ├── server.js
    ├── package.json
    ├── start-bridge.bat           ← запуск у Windows (подвійний клік)
    ├── start-bridge-lan.bat       ← те саме + доступ з телефонів
    └── start-bridge.sh            ← macOS / Linux
```

## 3. Іконки персонажів і полів

У Android-проєкті вони лежать у `app/src/main/assets/catalog/`. Скопіюйте:

| З Android-проєкту | У сайт |
|---|---|
| `app/src/main/assets/catalog/characters/*.png` | `assets/catalog/characters/` |
| `app/src/main/assets/catalog/maps/*.png` (або `map/`) | `assets/catalog/maps/` |

Імена файлів — це id з каталогу (наприклад, `medusa.png`, `marmoreal.png`), нічого перейменовувати не треба. Якщо файлу немає, замість іконки показується перша літера; власну іконку можна додати з галереї при додаванні/редагуванні персонажа (зберігається в браузері).

## 4. Запуск на комп'ютері (Windows)

1. Встановіть **Node.js LTS** — https://nodejs.org (звичайний інсталятор).
2. Відкрийте папку `bridge` і двічі клацніть **`start-bridge.bat`**. Перший раз він сам встановить залежності (потрібен інтернет).
3. У вікні з'явиться адреса `http://localhost:8765` — відкрийте її в браузері. Міст сам віддає й сайт, тож у цьому режимі **GitHub не потрібен**.
4. Для телефонів і планшетів у вашій Wi-Fi мережі запускайте **`start-bridge-lan.bat`** — він покаже адресу виду `http://192.168.0.10:8765`; відкрийте її на пристрої (працює й в **Safari на iPhone**).
   Якщо Windows спитає про брандмауер — натисніть «Дозволити доступ» для приватної мережі.

## 5. Як приєднатись до гри з Android

1. На телефоні-хості: застосунок → створити кімнату (він має бути в тій самій Wi-Fi мережі, що й комп'ютер).
2. На сайті: **«Приєднатися до гри»** (або 🌐 угорі). Міст підключиться автоматично — кнопка «Підключити» лише для іншої адреси мосту.
3. Оберіть знайдену гру зі списку. Якщо список порожній (деякі роутери блокують mDNS) — введіть **IP хоста** в «Вхід за адресою»; його показує кімната в застосунку («Адреса для входу вручну»).
4. У кімнаті ви бачите гравців, поле, персонажів і номери ходу, таймер, підтверджуєте результат, а в турнірі обираєте персонажів/поле. Результат записується у вашу статистику й історію, як в Android. Якщо зв'язок обірвався, сайт сам повертає вас на місце (до 2 хвилин).

Акаунт, статистика й дані зберігаються **в браузері** (окремо на кожному пристрої й у кожному браузері). Перенесення — через «Резервну копію».

## 6. Розміщення сайту на GitHub Pages

Безкоштовно, потрібен лише акаунт на github.com.

### Варіант А — через браузер (без Git)

1. Зайдіть на https://github.com → **New repository** (кнопка «+» праворуч угорі).
   *Repository name*: наприклад `unmatched` · **Public** · не ставте галочок «Add README» → **Create repository**.
2. На сторінці нового репозиторію натисніть **uploading an existing file**.
3. Відкрийте папку `UnmatchedWeb` у Провіднику, виділіть **усе її вміст** (`index.html`, `css`, `js`, `icons`, `assets`, `manifest.webmanifest`, `sw.js`, `.nojekyll`, `bridge` …) і перетягніть у вікно браузера. Папки переносяться з вмістом.
   Важливо: файли мають лежати **в корені** репозиторію (`index.html` — одразу на головній сторінці репозиторію, а не всередині папки `UnmatchedWeb`).
   Файл `.nojekyll` у Провіднику може бути прихований — увімкніть «Показувати приховані елементи» або створіть його на GitHub: *Add file → Create new file → ім'я `.nojekyll` → Commit*.
4. Унизу натисніть **Commit changes**.
5. Репозиторій → **Settings → Pages**. У розділі *Build and deployment*: *Source* — **Deploy from a branch**, *Branch* — **main**, папка **/ (root)** → **Save**.
6. Через 1–2 хвилини вгорі сторінки з'явиться адреса **`https://ВАШ-ЛОГІН.github.io/unmatched/`**. Відкрийте її.

### Варіант Б — через Git

```bash
cd шлях\до\UnmatchedWeb
git init
git add .
git commit -m "Unmatched web"
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГІН/unmatched.git
git push -u origin main
```
Далі — пункти 5–6 вище. Оновлення сайту: змініть файли, виконайте `git add . && git commit -m "update" && git push` (або знову завантажте файли через браузер) — за хвилину сайт оновиться. Якщо бачите стару версію — оновіть сторінку з Ctrl+F5.

### Мережеві ігри з сайту на GitHub Pages

GitHub Pages — це `https`, а міст — локальний. Щоб вони працювали разом:

1. Впишіть адресу свого сайту **без слеша в кінці й без шляху** у `bridge/start-bridge.bat` у рядок `set SITE=...` — наприклад `https://ivan.github.io` (шлях `/unmatched/` не потрібен). Так міст розуміє, що цьому сайту можна з ним з'єднуватись.
2. Запустіть `start-bridge.bat`, відкрийте свій сайт на GitHub Pages → «Приєднатися до гри». Адреса мосту за замовчуванням `ws://localhost:8765`.
3. Працює в **Chrome, Edge, Firefox** на тому ж комп'ютері. Нові версії Chrome можуть один раз спитати дозвіл на доступ до локальної мережі — натисніть «Дозволити».
4. **Safari/iPhone/iPad** не дозволяють сторінці з https з'єднуватись із локальним мостом. Для них відкривайте сайт з адреси, яку показує **`start-bridge-lan.bat`** (`http://IP-комп'ютера:8765`) — там усе працює.

Звичайна гра, турнір, статистика тощо працюють на GitHub Pages і без мосту, на будь-якому пристрої.

## 7. Що перевірено, а що ні

- **Перевірено автоматично:** тести з імітацією Android-хоста за протоколом `NetGame.kt` — вхід (challenge → join → welcome), стан кімнати, анімація, бій, обрив і повернення на місце з HMAC-доказом, турнірні повідомлення (`tsel`, `tok`); генерація 2/3/4 гравців із правильними номерами ходу; акаунти (PBKDF2, блокування спроб); статистика; експорт/імпорт; теми; мови; відсутність помилок JavaScript у браузерному середовищі (jsdom).
- **Не перевірено:** робота з реальним телефоном-хостом і реальним Wi-Fi (у мене немає доступу до вашої мережі), візуальний вигляд у реальних браузерах і на різних екранах, імпорт реальної резервної копії з вашого Android (формат відтворено за кодом, version 3). Якщо щось поведеться інакше — напишіть, виправлю.
- **Відомі відмінності від застосунку:** немає створення кімнати з сайту (обмеження браузера); карти офіційних арт-зображень для великої анімації не використовуються (показуються іконки); правила автоматичного злиття старих назв у каталозі спрощено (при додаванні офіційного персонажа сайт пропонує об'єднати його зі знайденим записом).

## 8. Якщо щось не працює

| Проблема | Що робити |
|---|---|
| «Не вдалося підключитись до мосту» | Запущено `start-bridge.bat`? Вікно не закрито? Адреса мосту `ws://localhost:8765`? Для GitHub Pages — вписано `SITE` у .bat? |
| Список ігор порожній | Телефон і комп'ютер в одній Wi-Fi? Деякі роутери (гостьова мережа, «ізоляція клієнтів») блокують mDNS — введіть IP хоста вручну. |
| «Не вдалося підключитись до гри» | Кімната на телефоні відкрита? Брандмауер Windows не блокує Node.js? IP/порт правильні (45678)? |
| Safari: міст «не підключено» | Відкривайте сайт з адреси `http://IP:8765` від `start-bridge-lan.bat`. |
| Стара версія сайту після оновлення | Ctrl+F5; на телефоні — закрити вкладку й відкрити знову. |
| Не збереглись дані | Режим «інкогніто» і очищення даних браузера стирають їх; робіть резервну копію. |
